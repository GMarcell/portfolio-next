# Grand Marcell — Portfolio

A modern, production-grade portfolio built with **Next.js 16**, **React 19**, and **TypeScript**. Features a contact form powered by Resend, dark/light theme with smooth view transitions, custom cursor effects, and scroll-triggered animations.

## Stack

| Layer | Technology |
|---|---|
| Framework | [Next.js 16](https://nextjs.org/) (App Router) |
| Language | [TypeScript](https://www.typescriptlang.org/) (strict) |
| Styling | [Tailwind CSS v4](https://tailwindcss.com/) |
| UI Primitives | [Base UI](https://base-ui.com/) (Switch, Button) |
| Animations | CSS `view-transition`, IntersectionObserver scroll-reveal, CSS keyframes |
| Email | [Resend](https://resend.com/) |
| Analytics | [Vercel Analytics](https://vercel.com/analytics) |
| Uptime | [UptimeRobot](https://uptimerobot.com/) (free tier) |
| Deployment | [Vercel](https://vercel.com/) (recommended) or any Node.js host |

## Requirements

- **Node.js** >= 20.9.0
- **npm** (included with Node.js)

## Getting Started

```bash
# 1. Clone the repository
git clone https://github.com/GMarcell/portfolio-next.git
cd portfolio-next

# 2. Install dependencies
npm install

# 3. Set up environment variables
cp .env.example .env.local
# Edit .env.local and add your RESEND_API_KEY

# 4. Start the development server
npm run dev
```

Open [http://localhost:3000](http://localhost:3000) in your browser.

## Environment Variables

Copy `.env.example` to `.env.local` and fill in the values.

| Variable | Required | Default | Description |
|---|---|---|---|
| `RESEND_API_KEY` | Yes | — | Resend API key for the contact form |
| `CONTACT_EMAIL` | No | `grand1310marcell@gmail.com` | Where contact messages are delivered |
| `CONTACT_FROM_EMAIL` | No | `onboarding@resend.dev` | "From" address on outgoing emails — use a domain verified in Resend, e.g. `Portfolio Contact <contact@grandmarcell.dev>` |
| `UPSTASH_REDIS_REST_URL` | No | — | Upstash Redis URL — enables distributed rate limiting across serverless invocations |
| `UPSTASH_REDIS_REST_TOKEN` | No | — | Upstash Redis token (pair with the URL above) |

`RESEND_API_KEY` is checked at build time by `scripts/validate-env.mjs` — the production build fails if it is unset. Without Upstash credentials the rate limiter falls back to a per-process in-memory store (fine for local dev).

## Production Checklist

Before deploying to production:

1. **Set up Resend**: Create an account at [resend.com](https://resend.com/), add a verified domain, and generate an API key.
2. **Configure email env vars**: Set `RESEND_API_KEY`, `CONTACT_FROM_EMAIL` (use your verified Resend domain), and `CONTACT_EMAIL` in your hosting platform.
3. **Enable distributed rate limiting (optional)**: Create a free Upstash Redis database and set `UPSTASH_REDIS_REST_URL` + `UPSTASH_REDIS_REST_TOKEN` so rate limits hold across serverless invocations.
4. **Confirm your domain**: If you deploy on anything other than `grandmarcell.dev`, update the URL in `app/layout.tsx`, `app/sitemap.ts`, and `app/robots.ts`.
5. **Replace the placeholder resume**: `public/resume.pdf` is a placeholder generated by `scripts/generate-placeholder-resume.py` — replace it with your actual resume before going live.
6. **Enable uptime monitoring**: Add the production URL to UptimeRobot (free tier) to get email alerts if the site goes down (see below).

## Deployment

### Vercel (recommended)

```bash
npm i -g vercel
vercel
```

Then, in the Vercel project dashboard (Settings → Environment Variables), add:

| Name | Value |
|---|---|
| `RESEND_API_KEY` | Your Resend API key |
| `CONTACT_FROM_EMAIL` | e.g. `Portfolio Contact <contact@grandmarcell.dev>` |
| `CONTACT_EMAIL` | e.g. `grand1310marcell@gmail.com` (optional) |
| `UPSTASH_REDIS_REST_URL` | Your Upstash URL (optional) |
| `UPSTASH_REDIS_REST_TOKEN` | Your Upstash token (optional) |

Once deployed, **enable Vercel Analytics** in the project dashboard (Analytics tab) — the `<Analytics />` component is already wired into the root layout, so no code changes are needed.

### Other Node.js hosts

Any host that runs Next.js serverless/server output works (Netlify, Railway, Fly.io, a VPS with Node.js, etc.). Netlify: connect the repo and use its built-in Next.js support — do not set a publish directory manually.

## CI/CD

This project includes a GitHub Actions workflow (`.github/workflows/ci.yml`) that runs lint, type-check, tests, and a production build on every push and pull request to the `main` branch. Add `RESEND_API_KEY` as a repository secret so the build passes the env validation (a placeholder is used if the secret is absent).

## Monitoring

- **Vercel Analytics** — traffic, referrers, and Core Web Vitals, with zero config once enabled in the dashboard.
- **UptimeRobot** (free) — monitor `https://grandmarcell.dev` every 5 minutes and get email alerts on downtime or SSL expiry.

## Security

- **Rate limiting**: The contact form API limits requests to 5 per 60 seconds per IP.
- **Content Security Policy**: Strict CSP headers are applied to all routes.
- **HTTPS enforced**: HSTS header with `includeSubDomains` and `preload`.
- **Security headers**: X-Content-Type-Options, X-Frame-Options, X-XSS-Protection, Permissions-Policy, and Referrer-Policy are all set.

## Lighthouse

The site is optimised for Lighthouse performance with:
- Targeted CSS transitions (no universal `*` transitions)
- `content-visibility: auto` on below-fold sections
- GPU-composited cursor and ticker animations (`translate3d`, `will-change`)
- Pre-rendered PNG noise instead of SVG `feTurbulence`
- `display: swap` font loading with preconnect hints
- Production source maps disabled
